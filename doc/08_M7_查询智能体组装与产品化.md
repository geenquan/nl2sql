# M7–M8 实现手册：查询智能体组装与产品化治理

## 1. 目标

把已经验证的业务语义层、NL2SQL、图表和反馈能力封装为可配置的查询型智能体，并补齐部署、权限、任务监控、版本管理和数据漂移治理。

## 2. 输入

- 已发布语义模型；
- NL2SQL 查询 API；
- 数据集和图表服务；
- 用户、角色与权限策略；
- LLM 与工具配置。

## 3. 输出展示形态

### 智能体配置页
名称、业务主题、系统指令、可用工具、模型配置、访问范围、最大执行步数、超时和成本限制。

### 工具清单
- `search_business_schema`
- `get_metric_definition`
- `generate_sql`
- `validate_sql`
- `execute_readonly_query`
- `render_chart`
- `explain_result`
- `submit_feedback`

工具名称为建议示例，实际实现需要定义输入输出 Schema 和权限要求。

### 试运行面板
显示每一步调用、参数摘要、执行状态、耗时、SQL 与结果引用。敏感值应脱敏。

### 运维面板
展示数据源状态、扫描任务、关系过期、数据集刷新、查询失败、模型成本和审计记录。

## 4. 智能体架构

推荐将智能体作为有边界的工作流，而不是任意自主执行程序：

1. 接收问题；
2. 检索语义；
3. 规划查询；
4. 调用 SQL 生成；
5. 调用安全校验；
6. 执行只读查询；
7. 解释结果；
8. 返回结果并记录反馈。

每一步都有明确输入输出、最大重试次数和失败分支。智能体不得绕过 SQL 安全层直接访问数据库。

## 5. 工具接口契约

每个工具必须定义：
- 名称和描述；
- JSON 输入 Schema；
- JSON 输出 Schema；
- 权限范围；
- 超时和重试；
- 幂等性；
- 错误码；
- 审计字段；
- 是否允许向模型返回数据样本。

若需要通过 MCP 暴露能力，应把工具 API 封装成受控接口；MCP 不是权限体系的替代品。

## 6. 自动组装原则

可以自动生成：
- 数据源与语义模型绑定；
- 可用主题和指标清单；
- 查询工具配置；
- 图表推荐配置；
- 系统提示词模板；
- 权限与预算默认值；
- 回归测试任务。

不应自动生成并启用：
- 任意写数据库工具；
- 无限制的 shell/代码执行；
- 未审核的高风险业务操作；
- 能绕过权限的数据导出能力。

## 7. 产品化任务

1. 多数据源配置和租户隔离；
2. 密钥管理；
3. 任务队列、重试和取消；
4. 审计日志与成本统计；
5. 关系和语义版本管理；
6. Schema/数据漂移检测；
7. 数据集刷新和失败恢复；
8. 安全策略与字段权限；
9. 部署脚本、容器和配置说明；
10. 备份、恢复和升级测试。

## 8. 漂移检测

触发重新验证的情况：
- 表或字段被删除/重命名；
- 字段类型变化；
- 关系匹配率显著变化；
- 唯一率或空值率异常变化；
- 业务指标突然大幅波动；
- 数据集生成 SQL 依赖失效。

漂移检测只应标记影响范围并触发验证，不能未经检查就自动覆盖生产语义模型。

## 9. 验收

- [ ] 智能体只能调用授权工具；
- [ ] 每次工具调用可审计；
- [ ] 有最大步数、重试、超时和成本限制；
- [ ] 数据源、租户与用户权限隔离；
- [ ] Schema 漂移可以识别；
- [ ] 关系/语义版本可回滚；
- [ ] 部署与升级有可复现步骤；
- [ ] 错误和告警能定位到具体任务。

## 10. 最终演示

从新建数据源开始，展示：
1. 元数据扫描；
2. 关系候选与人工确认；
3. 业务主题与视图生成；
4. 质量检查；
5. 自然语言查询；
6. SQL 与结果解释；
7. 智能体工具调用记录；
8. 修改字段或关系后触发漂移检测；
9. 回滚到上一稳定版本。
