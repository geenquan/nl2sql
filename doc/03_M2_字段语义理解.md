# M2 实现手册：字段语义理解与表用途分类

## 1. 目标

利用元数据、画像、语义检索和大模型，为表和字段生成结构化语义候选。模型必须允许“不确定”，不能将猜测伪装成事实。

## 2. 输入

- M1 的表、字段、约束和画像；
- 可选的业务术语表；
- 脱敏样本摘要；
- 模型与 Embedding 配置。

## 3. 输出展示形态

### 字段语义列表
字段、原始注释、建议业务名、语义类别、候选实体、置信等级、审核状态。

### 字段语义详情
展示模型解释、支持证据、替代解释、相似字段、模型版本和人工修改记录。

### 表用途分类
主数据/台账、交易/事件、明细、字典、日志/历史、关系表、未知等候选类别。

### 语义搜索
输入“设备所属组织编码”等概念，检索可能匹配的字段，并显示匹配原因。

## 4. 语义类别建议

`entity_identifier`、`foreign_identifier_candidate`、`name`、`description`、`status`、`category`、`timestamp`、`date`、`quantity`、`amount`、`measurement`、`organization_identifier`、`free_text`、`unknown`。

类别应可扩展，不要把行业专属概念写死在核心代码中。

## 5. 实现步骤

1. 对字段名进行中英文、缩写和分隔符拆词；
2. 构建字段特征：类型、注释、唯一率、空值率、基数、样本摘要；
3. 使用规则识别常见字段角色；
4. 使用 Embedding 检索相似字段与术语；
5. 构造受控提示词，要求模型输出符合 JSON Schema 的结构；
6. 要求每个推断附带证据，并允许返回 `unknown`；
7. 对输出做 JSON Schema 校验；
8. 保存推断结果、模型版本、提示词版本；
9. 实现人工修改和审核；
10. 将确认结果用于后续检索，但暂不自动训练模型。

## 6. 提示词原则

- 只提供必要元数据和脱敏统计摘要；
- 明确“语义相似不代表可以 JOIN”；
- 不允许模型根据行业常识直接确定状态码；
- 对冲突解释保留候选；
- 不确定时返回 `unknown`；
- 要求证据可由元数据或画像核验。

## 7. 评测

人工标注一批字段和表，评估：
- 表用途分类准确率；
- 字段语义类别准确率；
- 候选实体准确率；
- unknown 使用合理性；
- 证据可核查率；
- JSON 输出合格率；
- 人工修订率；
- 推理耗时和成本。

## 8. 验收

- [ ] 输出结构化且可追溯；
- [ ] 支持 unknown 和多个备选解释；
- [ ] 模型版本与提示词版本可查询；
- [ ] 人工修订会保留历史；
- [ ] 敏感数据不会违规发送；
- [ ] 语义相似度不会直接被当作关系成立证据。

## 9. 演示步骤

选择一张设备表和一张缺陷表，展示原始字段、模型建议、证据、候选实体和人工修订。再输入一个业务术语，展示语义检索结果。
