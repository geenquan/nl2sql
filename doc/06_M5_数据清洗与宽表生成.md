# M5 实现手册：数据清洗、主题视图与宽表生成

## 1. 目标

基于已验证关系和语义模型，自动生成一个明确主题的普通视图、宽表或聚合表，并通过数据质量测试与业务对账后再发布。

## 2. 输入

- M4 已发布或获准使用的语义模型；
- 目标主题；
- 目标粒度；
- 允许的来源表和字段；
- 刷新要求、权限和查询预算。

## 3. 输出展示形态

### 数据集构建向导
选择主题、中心实体、字段、指标、过滤条件、刷新方式。

### SQL 预览
展示生成 SQL、使用的关系路径、聚合规则和来源字段。支持只读预览，不自动发布。

### 数据预览
展示前 N 行、总行数估计、字段说明和生成时间。

### 质量报告
展示行数、主键唯一率、空值、异常重复、JOIN 覆盖率、指标对账、测试失败详情。

### 数据集版本页
展示版本、SQL、来源、刷新状态、质量结果、发布时间与回滚操作。

## 4. 生成流程

1. 选择业务主题；
2. 明确“一行代表什么”；
3. 选取已验证关联路径；
4. 区分维度、明细字段与聚合指标；
5. 识别一对多和多对多；
6. 对明细表先按目标粒度聚合；
7. 生成 SQL；
8. 在隔离目标 Schema 执行；
9. 运行质量测试；
10. 对照标准查询/指标进行对账；
11. 通过后发布；
12. 保存版本和回滚点。

## 5. 物理实现选择

- 普通视图：初期优先，便于检查逻辑且不复制数据；
- 物化视图/宽表：高频查询、计算昂贵且可接受刷新延迟；
- 聚合表：指标定义稳定、查询粒度固定；
- 动态 JOIN：多样查询需要、关系路径可信。

不要为了“有宽表”而把所有表都物化到一张巨表中。

## 6. 关键正确性规则

### 6.1 防止一对多膨胀
若设备有 5 条缺陷、3 条工单记录，直接同时 JOIN 可能得到 15 行。应先分别按设备聚合，再关联设备主题。

### 6.2 不随意清洗业务值
- 空值不一律填 0；
- 未知状态码不随意映射；
- 重复记录不直接删除；
- 日期格式转换失败应保留异常标记；
- 编码映射必须有证据和规则来源。

### 6.3 质量测试
- 主键/粒度唯一性；
- 必填字段完整率；
- JOIN 匹配率；
- 行数变化；
- 指标对账；
- 值域与格式约束；
- 刷新前后异常波动。

## 7. SQL 生成与执行安全

- SQL 只能访问白名单来源；
- 不允许 DDL/DML；
- 执行前解析 SQL 并检查方言；
- 目标对象必须在独立 Schema；
- 设置超时、扫描和存储预算；
- 发布前必须通过质量门槛；
- 生成 SQL、执行结果和测试结果均需版本化。

## 8. 验收

- [ ] 主题粒度明确；
- [ ] SQL 可预览、可解释；
- [ ] 质量测试自动执行；
- [ ] 多个一对多关系不会无意放大指标；
- [ ] 关键指标与标准结果对账；
- [ ] 失败数据集不能发布；
- [ ] 版本可比较、可回滚；
- [ ] 刷新失败可重试并保留错误原因。

## 9. 演示

生成“设备主题”视图：一行一台设备，包含设备名称、所属组织、缺陷总数、未处理缺陷数、最近缺陷时间。展示 SQL、前 20 行、质量报告，并证明设备数量不会因缺陷明细重复而膨胀。
