# M3 实现手册：跨表关系发现与验证

## 1. 目标

从缺少外键和数据字典的数据库中，召回候选字段关系，通过结构、统计、语义和 JOIN 结果证据评估关系可信度，并提供关系图与审核工作台。

## 2. 输入

- M1 元数据和画像；
- M2 字段语义卡片；
- 可执行的只读查询能力；
- 人工核实的关系真值集。

## 3. 输出展示形态

### 关系候选表
展示源表/字段、目标表/字段、候选基数、值域覆盖率、唯一率、语义相似度、总等级、状态。

### 关系详情
展示支持/反对证据、JOIN 前后行数、匹配样本（脱敏）、空值影响、可能风险和替代字段。

### 关系图
节点表示表或实体，边表示候选关系；边样式区分候选、待确认、已验证、已拒绝和过期关系。

### 审核操作
通过、拒绝、待补充证据；记录审核人、时间、原因和版本。

## 4. 候选召回

使用多策略生成候选：
- 字段类型兼容；
- 字段名和注释相似；
- Embedding 语义相似；
- 唯一率与基数模式；
- 值域重叠或包含；
- 外键、索引等结构证据；
- 相同候选实体。

禁止对所有字段对做无约束笛卡尔积。按类型、语义、Schema、实体候选和 Top-K 限制候选规模。

## 5. 证据计算

至少考虑：
- 类型兼容度；
- 字段名/语义相似度；
- 值域重合率；
- A→B 和 B→A 的覆盖率；
- 源端唯一率；
- 目标端重复分布；
- NULL、空字符串和默认值影响；
- JOIN 后行数变化；
- 关系路径与其他已验证关系是否冲突。

不要把单个高值当成结论。字段值相同可能是巧合、共享编码或同名但不同含义。

## 6. JOIN 验证

- 先估算查询成本；
- 只对高优先级候选执行精确检查；
- 限制超时、扫描量和返回行数；
- 计算匹配率、未匹配率、基数和重复；
- 检查多对多造成的行数膨胀；
- 必要时按租户、组织、时间或状态条件分层验证；
- 保存 SQL 模板、参数摘要和验证结果。

## 7. 关系状态机

`candidate → evidence_collected → validated / needs_review / rejected`。源 Schema 或数据分布变化后，已验证关系可变为 `stale`，需重新检查。

## 8. 多跳路径

在已验证关系图上搜索路径，限制最大跳数。路径评分应考虑：
- 每条关系的可信度；
- JOIN 成本；
- 粒度兼容性；
- 多对多风险；
- 业务语义合理性；
- 时间有效性。

图上可连通不等于业务上可以直接连接。

## 9. 评测

建立正例和负例，包括：
- 有外键关系；
- 无外键但真实业务关系；
- 编码映射关系；
- 时间关联；
- 字段相似但不应 JOIN 的负例。

计算 Precision、Recall、F1、基数判断准确率、高置信错误率、多跳路径准确率、单候选成本。与字段名规则基线和单次 LLM 基线比较。

## 10. 验收

- [ ] 候选关系均有证据；
- [ ] 关系状态与证据可查看；
- [ ] 未验证关系默认不进入生产查询；
- [ ] JOIN 验证受资源预算限制；
- [ ] 支持审核、拒绝、过期和重验；
- [ ] 可展示关系图；
- [ ] 在标注集上与基线比较；
- [ ] 不把未经校准的分数称为概率。

## 11. 演示

输入 M1/M2 结果，运行候选发现；打开一条候选关系，展示值域覆盖、基数和 JOIN 验证；拒绝一条错误关系；确认一条真实关系；查看关系图状态更新。
