# M0 实现手册：工程骨架与评测集

## 1. 目标

建立可运行、可测试、可持续扩展的项目骨架，并准备最小可用的演示数据库、关系真值集和 NL2SQL 标准问题集。M0 不实现自动关系推断或 NL2SQL。

## 2. 输入

- 开发环境与代码仓库；
- 预期运行方式（本地开发优先）；
- 一份可合法使用的脱敏数据库或合成数据；
- 首个业务主题，如设备、缺陷或工单。

## 3. 输出展示形态

### 用户/开发者看到
- README 中一键启动说明；
- API 健康检查返回 `{"status":"ok"}`；
- 环境配置模板 `.env.example`；
- 自动化测试报告；
- 样例数据和评测数据目录；
- 项目目录结构说明。

### 建议目录结构

```text
app/
  api/
  core/
  config/
  db/
  connectors/
  metadata/
  profiling/
  semantics/
  relationships/
  datasets/
  nl2sql/
  agents/
  security/
  observability/
tests/
  unit/
  integration/
  fixtures/
evals/
  relationship_gold/
  nl2sql_questions/
docs/
scripts/
```

首版可以按实际规模简化，但模块边界应清晰。

## 4. 实现任务

1. 初始化 Python 项目、依赖锁定与代码格式化；
2. 建立配置管理与环境变量读取；
3. 建立统一日志格式和 request/job ID；
4. 建立 FastAPI 应用与健康检查；
5. 建立数据库迁移框架；
6. 建立单元测试和集成测试；
7. 创建脱敏样例数据库或合成数据；
8. 定义关系真值集格式；
9. 定义 NL2SQL 问题集格式；
10. 编写 Claude Code 开发约定。

## 5. 评测数据格式

### 关系真值集示例

```json
{
  "source_table": "T_DEVICE",
  "source_column": "DEV_ID",
  "target_table": "T_DEFECT",
  "target_column": "OBJ_CODE",
  "expected_relation": true,
  "expected_cardinality": "one_to_many",
  "evidence_note": "经业务人员核实"
}
```

### NL2SQL 问题集示例

```json
{
  "question_id": "q001",
  "question": "各组织未处理缺陷数量是多少？",
  "standard_sql": "SELECT ...",
  "expected_result_file": "q001.csv",
  "metric_definition": "按缺陷唯一标识去重，仅统计未处理状态",
  "difficulty": "multi_table"
}
```

所有示例 SQL 必须针对真实测试 Schema 编写，不能把省略号作为可执行 SQL。

## 6. 验收清单

- [ ] 新环境按 README 可启动；
- [ ] 配置缺失时给出明确错误；
- [ ] 健康检查可访问；
- [ ] 单元测试命令可运行；
- [ ] 集成测试有可选的测试数据库；
- [ ] 不含真实密码或敏感数据；
- [ ] 关系真值集和问题集格式已定义；
- [ ] 日志不记录凭证；
- [ ] 代码检查与格式化工具已配置。

## 7. Claude Code 执行要求

先提交工程结构方案，再逐步创建文件。不得一次性生成后续所有模块。完成后提供目录树、启动命令、测试结果和一条 API 调用示例。
