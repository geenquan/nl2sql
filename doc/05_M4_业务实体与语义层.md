# M4 实现手册：业务实体与语义层构建

## 1. 目标

把字段语义和已验证关系组织成统一、版本化的业务语义模型，为宽表生成和 NL2SQL 提供一致的实体、属性、关系、指标和查询路径。

## 2. 输入

- M2 字段语义结果；
- M3 已验证关系；
- 可选业务术语与少量人工确认；
- 业务问题集。

## 3. 输出展示形态

### 业务主题页面
展示主题名称、中心实体、包含的表、字段、关系、数据集和支持的问题类型。

### 实体详情
展示标准名、别名、主标识、属性、来源表、语义状态和权限标签。

### 指标卡片
展示指标名称、计算表达式、统计粒度、过滤条件、去重键、时间口径、单位和确认状态。

### 语义模型导出
导出 JSON/YAML，可用于版本控制、审查和下游转换。

## 4. 核心对象

- Entity：业务实体；
- Attribute：实体属性；
- Relationship：实体关系、连接条件、基数、状态；
- Metric：指标及其统计口径；
- Dimension：筛选、分组和排序维度；
- QueryPath：回答特定问题所需的关联路径；
- Policy：权限、敏感字段和查询限制；
- Evidence：来源、推断理由、审核和版本。

## 5. 实现步骤

1. 从字段语义卡片聚合实体候选；
2. 用已验证关系连接实体；
3. 区分主数据、事件表、明细表、历史表和桥接表；
4. 为每个主题定义中心实体和粒度；
5. 识别候选维度和候选指标；
6. 为指标保存表达式、过滤条件、去重键和时间口径；
7. 为常见业务问题生成候选查询路径；
8. 检测循环、歧义路径、多对多风险和粒度冲突；
9. 生成可审查的语义模型；
10. 支持版本、差异比较和回滚。

## 6. 指标口径治理

“设备数量”可能指当前有效设备、某组织设备、某时点设备或去重设备 ID。模型可以生成候选定义，但正式发布前应根据证据和业务要求标记为：
- `suggested`
- `data_validated`
- `business_confirmed`
- `published`

没有确认的指标不能被伪装成已确定口径。若无法自动消歧，应向用户呈现候选口径。

## 7. 与现有语义工具的关系

可将自有规范化语义模型映射到 Cube、dbt 或 NL2SQL 上下文。不要把第三方工具作为唯一事实存储；保留自有模型便于切换实现。

## 8. 验收

- [ ] 实体与字段映射有来源；
- [ ] 关系只使用已验证或明确标注的候选；
- [ ] 每个主题定义粒度；
- [ ] 指标包含聚合与时间口径；
- [ ] 多条查询路径的歧义可被检测；
- [ ] 语义模型可以导出、版本化和回滚；
- [ ] 未确认指标不会默认发布。

## 9. 演示

选择“设备主题”，展示中心实体、设备属性、缺陷关系、缺陷数量候选指标和粒度说明。导出 YAML 后，修改一个关系并展示版本差异。
