# M6 实现手册：NL2SQL 查询闭环与结果验证

## 1. 目标

让用户通过自然语言查询已发布的业务语义层，系统返回可解释的 SQL、查询结果和图表，并对执行安全、业务口径和结果准确性进行验证。

## 2. 输入

- 已发布的语义模型和主题视图；
- 用户自然语言问题；
- 用户身份与权限；
- LLM 配置；
- 标准问题集和标准 SQL。

## 3. 输出展示形态

### 对话界面
显示用户问题、系统理解的指标/维度/时间范围、歧义提示。

### SQL 卡片
展示 SQL、使用的主题、字段和关联路径、执行状态、耗时。

### 结果表与图表
展示数据结果、单位、过滤条件、统计口径、数据更新时间。

### 诊断面板
显示 SQL 解析错误、权限拦截、空结果、超时、结果对账状态。

### 反馈操作
用户可标记正确/错误、说明口径差异，并关联到具体问题和语义版本。

## 4. 查询处理流水线

1. 识别意图；
2. 从语义层检索相关实体、指标、维度和术语；
3. 解析过滤条件、时间范围和分组要求；
4. 选择可信查询路径；
5. 生成 SQL；
6. 解析并执行安全检查；
7. 只读执行；
8. 检查错误、空结果和异常行数；
9. 对可验证问题进行结果校验；
10. 生成解释和合适的图表；
11. 记录反馈和评测数据。

## 5. NL2SQL 上下文策略

不要把整个数据库 Schema 一次性发给模型。只提供：
- 当前问题相关的主题；
- 允许使用的字段；
- 已验证关系和连接条件；
- 指标定义和粒度；
- 业务术语及同义词；
- SQL 方言和权限限制；
- 少量经过脱敏的示例。

模型生成的 SQL 必须视为不可信内容，不能只靠系统提示词约束。

## 6. SQL 安全层

至少执行：
- SQL AST 解析；
- 仅允许 SELECT 或明确允许的只读查询形式；
- 阻止 INSERT/UPDATE/DELETE/DDL、多语句；
- 限制表、列和函数白名单；
- 注入用户权限过滤；
- 超时、返回行数、并发和扫描量限制；
- 对敏感字段脱敏；
- 记录 SQL 摘要、用户、数据源、执行时间和结果状态。

不要使用简单字符串搜索作为唯一安全机制。

## 7. 结果正确性

区分：
- SQL 语法正确；
- SQL 能成功执行；
- 结果集正确；
- 业务口径正确。

标准问题集应保存标准 SQL、结果和口径说明。结果比较应考虑行顺序、浮点误差、日期时区、NULL、精度和非确定性。

对于开放式问题，如果无法自动判断结果正确，应显示使用的口径和来源，不要声称“已验证正确”。

## 8. 纠错策略

- 语法错误：根据数据库错误信息有限次修复；
- 列名不存在：回到语义层重新检索；
- 关系歧义：要求用户选择或采用已验证路径；
- 空结果：检查过滤条件和时间范围，不能擅自放宽权限；
- 超时：提示优化或使用聚合数据集；
- 指标口径不确定：给出候选定义，而不是随意选择。

限制修复轮数与 token/时间预算，避免无限循环。

## 9. 评测

- SQL 执行成功率；
- 结果集准确率；
- 业务口径准确率；
- 多表 JOIN 准确率；
- 复杂问题准确率；
- 越权拦截率；
- 延迟和成本；
- 人工修订次数。

至少比较两组：
A. 原始 Schema 直接生成 SQL；
B. 使用自动生成的语义层与主题视图生成 SQL。

保持模型、问题集和数据库快照一致，才能衡量语义层的实际贡献。

## 10. 验收

- [ ] 用户可查看 SQL 和统计口径；
- [ ] SQL 安全检查在执行前完成；
- [ ] 越权与写操作被阻止；
- [ ] 结果与标准集可自动比较；
- [ ] 纠错有次数和成本限制；
- [ ] 查询失败有可解释错误；
- [ ] 用户反馈可追踪到模型/语义版本；
- [ ] 结果准确率与原始 Schema 基线完成对比。

## 11. 演示

输入“各组织本月未处理缺陷数量是多少”，展示系统识别的时间范围、指标口径、关联路径、SQL、结果表和图表。再输入一个越权问题，展示安全拦截。
